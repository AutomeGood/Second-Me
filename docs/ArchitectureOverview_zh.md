# 架构概览

本文档旨在提供系统架构的高层概览，重点介绍其 AI 功能的分层方法，这些功能主要集中在 `lpm_kernel` 中。该架构设计为分层结构（L0、L1、L2），以分离关注点并构建日益复杂的人工智能能力。

## L0 - 核心 AI 层

*   **目的**: L0 层负责与大型语言模型（LLM）的直接交互。它处理基础任务，例如提示词构建、向各种 LLM 后端（本地或基于 API，如 Ollama、OpenAI）发送请求，以及接收原始的 LLM 生成的响应。
*   **关键组件 (示例来自 `lpm_kernel/L0/`)**:
    *   `l0_generator.py`: 包含生成文本的核心逻辑。它可能抽象了不同 LLM 提供商的复杂性，并管理请求/响应周期。
    *   `prompt.py`: 提供用于创建、格式化和自定义发送给 LLM 的提示词的实用工具和模板。
    *   `models.py`: 定义 L0 输入（例如，提示词配置）和输出（例如，原始 LLM 响应）的数据结构。
*   **交互**: L0 从更高层（L1、L2）或直接从 API 服务接收生成请求。然后，它与配置的 LLM 交互，并返回未经处理或最低限度处理的输出。

## L1 - Persona 及智能体层

*   **目的**: L1 层建立在 L0 之上，以实现更专业化和由 Persona 驱动的 AI 行为。它专注于赋予 AI 一致的性格，生成与该 Persona 一致的内容（如个人简介、状态更新或专题回应），并可能管理类似智能体的交互或决策。
*   **关键组件 (示例来自 `lpm_kernel/L1/`)**:
    *   `l1_generator.py`: 协调各种 L1 功能，将 L0 输出与 Persona 约束相结合。
    *   `bio.py`, `status_bio_generator.py`, `topics_generator.py`, `shade_generator.py`: 这些模块可能负责生成 AI Persona 或角色的特定方面，例如其背景故事、当前状态、专业领域，甚至是细微的个性特征（“shades”）。
    *   `prompt.py`: 包含 L1 特定的提示工程技术，调整 L0 提示以从 LLM 引出与 Persona 一致的响应。
*   **交互**: L1 利用 L0 执行核心 LLM 生成任务。它接收请求（例如，“为 Persona X 生成简介”）并向更高层（L2）或直接向应用程序的 API 提供更结构化、具有 Persona 感知的输出。

## L2 - 知识与记忆层

*   **目的**: L2 层对于使 AI 能够学习、记忆并随时间提供与上下文相关的响应至关重要。它处理长期记忆、从各种数据源检索知识、用于摄取和结构化知识的数据处理管道，以及潜在的模型微调（例如，使用直接偏好优化 - DPO）以使 LLM 行为与用户偏好或特定知识领域保持一致。
*   **关键组件 (示例来自 `lpm_kernel/L2/` 和 `lpm_kernel/file_data/`)**:
    *   `l2_generator.py`: 协调 L2 功能，特别是需要记忆检索和上下文理解的聊天交互。
    *   `memory_manager.py`: 负责管理和访问 AI 记忆的核心组件。这可能涉及与向量数据库（ChromaDB）进行语义搜索的交互，以及与关系数据库（SQLite）进行结构化记忆或元数据交互。
    *   `data_pipeline/`: 包含用于将原始数据（例如，用户文档）处理成可用知识的工具和脚本。这包括像 `graphrag_indexing/` 这样的子模块，用于创建知识图谱或结构化索引。
    *   `dpo/`: 包括与直接偏好优化相关的脚本和模块，允许根据收集的偏好数据对 LLM 进行微调。
    *   `file_data/` (一个为 L2 提供数据的紧密相关的模块):
        *   `embedding_service.py`: 为文本数据生成向量嵌入。
        *   `document_service.py`: 管理文档处理和存储。
        *   `chunker.py`: 将文档分割成可管理、语义相关的块，以便进行嵌入和检索。
*   **交互**: L2 与 L0/L1 交互以生成通过检索到的知识增强的响应。它使用存储后端（SQLite 用于结构化数据/元数据，ChromaDB 用于向量嵌入）来持久化和查询记忆。它向应用程序 API 提供高级别的聊天和交互功能，从而实现具有上下文感知能力的对话。

## 数据流图

以下是 Mermaid.js 图表，说明了系统内的典型数据流。

### 记忆摄入流程

此图显示了用户上传的文档如何被处理并存储以供后续检索。

```mermaid
graph LR
    A[用户通过 API 上传] --> B(lpm_kernel/api/);
    B --> C{file_data 模块};
    C -- 文本提取、分块 --> D(embedding_service.py);
    D -- 生成嵌入向量 --> E{L2 层};
    E -- 存储文本块与嵌入向量 --> F(memory_manager.py);
    F --> G[ChromaDB (向量存储)];
    F --> H[SQLite DB (元数据)];
```

### 聊天交互流程

此图说明了如何使用分层架构处理用户查询，以生成与上下文相关且具有 Persona 感知的响应。

```mermaid
graph LR
    subgraph 用户交互
        A[用户通过 API 查询]
    end

    subgraph 系统处理
        A --> B(lpm_kernel/api/);
        B --> C{L2 层 - l2_generator.py};
        C -- 查询上下文 --> D(memory_manager.py);
        D -- 检索相关文本块 --> C;
        C -- 丰富的上下文与查询 --> E{L1 层 - l1_generator.py};
        E -- 构建 Persona 感知的提示 --> F{L0 层 - l0_generator.py};
        F -- 发送提示到 LLM --> G[LLM (本地/远程)];
        G -- LLM 原始响应 --> F;
        F -- 返回响应到 L1 --> E;
        E -- 后处理与结构化响应 --> C;
        C -- 最终响应准备 --> B;
    end

    subgraph API 响应
        B --> H[API 响应给用户]
    end
```

## 支撑组件

虽然 L0、L1 和 L2 层构成了核心 AI 逻辑，但还有其他几个组件支持其运行：

*   **`lpm_kernel/api/`**: 此模块是 L0、L1 和 L2 层提供的功能的主要入口点。它公开了 HTTP API，供前端或其他外部服务进行交互。
*   **`lpm_kernel/common/`**: 包含跨不同层使用的共享实用工具和抽象。这可能包括 LLM 交互的包装器、数据库会话管理、通用数据结构和日志记录实用工具。
*   **`lpm_kernel/configs/`**: 管理系统范围的配置，例如路径、LLM 设置、数据库连接详细信息以及其他操作参数，通常从 `.env` 文件或其他配置源加载。

这种分层架构允许模块化开发、更轻松的维护，并能够通过构建于基础组件之上来逐步增强 AI 的能力。
