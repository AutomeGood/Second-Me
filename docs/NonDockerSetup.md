# Non-Docker Local Setup Guide

This guide provides step-by-step instructions for setting up, starting, configuring, and stopping the application and its services (including Llama.cpp server) in a local, non-Docker environment using the provided Python scripts.

## Prerequisites

Before you begin, ensure you have the following tools installed:

*   **Python**: Version 3.12 or higher.
    *   Check: `python --version` or `python3 --version`
*   **Node.js**: Version 18 or higher (includes npm).
    *   Check: `node -v`
*   **npm**: Typically installed with Node.js.
    *   Check: `npm --version`
*   **CMake**: For compiling Llama.cpp.
    *   Check: `cmake --version`
*   **Poetry**: For Python dependency management.
    *   Check: `poetry --version`
    *   Installation: Follow the [official Poetry installation guide](https://python-poetry.org/docs/#installation).
*   **SQLite**: For the application database.
    *   Check: `sqlite3 --version`
*   **C++ Compiler**: Required for Llama.cpp.
    *   Linux: g++ or clang (e.g., `sudo apt-get install build-essential`)
    *   macOS: Apple Clang (Xcode Command Line Tools: `xcode-select --install`)
    *   Windows: MSVC (Visual Studio with C++ workload)

## Initial Setup

1.  **Clone the Repository**:
    ```bash
    git clone <repository_url> # Replace <repository_url> with the actual URL
    cd <repository_name>      # Replace <repository_name> with the cloned directory name
    ```

2.  **Environment Configuration (`.env` file)**:
    This project uses a `.env` file for configuration. Create a file named `.env` in the root of the project directory and populate it with the following essential variables. Adjust paths and ports as needed for your local environment.

    ```env
    # Base directory for models, data, and other resources
    # Example for Linux/macOS:
    LOCAL_BASE_DIR=./resources 
    # Example for Windows (ensure to use forward slashes or escape backslashes):
    # LOCAL_BASE_DIR=C:/GraphRAG/resources

    # Ports for services
    LOCAL_APP_PORT=8002
    LOCAL_FRONTEND_PORT=3000

    # Database and Log paths (usually relative to LOCAL_BASE_DIR or project root)
    CHROMA_PERSIST_DIRECTORY=${LOCAL_BASE_DIR}/data/chroma_db 
    SQLITE_DB_PATH=${LOCAL_BASE_DIR}/data/sqlite/lpm.db
    LOCAL_LOG_DIR=./logs

    # --- Model Configuration (Example - adjust as per your model needs) ---
    # These variables might be crucial if scripts like init_chroma.py depend on them during setup.
    # Ensure these are set if your setup process relies on specific model configurations.
    # Example:
    # LLM_PROVIDER=ollama
    # OLLAMA_EMBEDDING_MODEL_NAME=nomic-embed-text
    # OLLAMA_BASE_URL=http://localhost:11434
    # OLLAMA_CHAT_MODEL_NAME=mistral:7b-instruct-v0.2-q4_K_M
    # OPENAI_API_KEY=your_openai_api_key_if_using_openai
    # OPENAI_CHAT_MODEL_NAME=gpt-3.5-turbo
    # OPENAI_EMBEDDING_MODEL_NAME=text-embedding-ada-002

    # Host address (usually 127.0.0.1 for local setup)
    HOST_ADDRESS=127.0.0.1
    ```
    **Note**: Ensure `LOCAL_BASE_DIR` points to an existing directory or a location where the application can create it. The setup script will create subdirectories like `data/chroma_db` and `data/sqlite` under this path if they don't exist.

3.  **Running the Setup Script**:
    This script checks dependencies, sets up the Python environment using Poetry, compiles Llama.cpp, and installs frontend dependencies.
    ```bash
    python scripts/setup.py
    ```
    *   Review the console output for any errors.
    *   Detailed logs can be found in `logs/setup.log` (this might be console-only if `setup.py` is not configured for file logging; refer to its output).

4.  **Activating the Python Environment**:
    After `setup.py` completes, activate the Poetry virtual environment:
    *   **Recommended**:
        ```bash
        poetry shell
        ```
    *   **Alternative**:
        *   On Linux/macOS: `source activate-poetry-env.sh` (This script should be generated by `setup.py` in the project root).
        *   On Windows: `activate-poetry-env.bat` (This script should be generated by `setup.py` in the project root).

## Starting the Services

Once the setup is complete and the Python environment is activated:

1.  **Start all services (Backend and Frontend)**:
    ```bash
    python scripts/start.py
    ```
    This command starts the backend server and the frontend development server.

2.  **Start Backend Only**:
    If you only need the backend running (e.g., for API access):
    ```bash
    python scripts/start.py --backend-only
    ```

3.  **Verification**:
    *   The console output from `start.py` will indicate the URLs where the services are accessible (e.g., Backend: `http://localhost:8002`, Frontend: `http://localhost:3000`).
    *   Check the following log files for detailed output and errors:
        *   `logs/start.log` (for the start script itself)
        *   `logs/backend.log` (for the backend application)
        *   `logs/frontend.log` (for the frontend development server)

## Stopping the Services

To stop all services initiated by `start.py`:

1.  **Stop all services**:
    ```bash
    python scripts/stop.py
    ```
    This script stops the backend, frontend, and attempts to clean up any Llama server processes started by the backend.

2.  **Stopping Llama Server on a Custom Port**:
    If the Llama server (potentially started by `scripts/start_local.sh` which is called by `scripts/start.py`) is running on a non-default port (default assumed by `stop.py` is 8080 for direct Llama server cleanup), you can specify its port:
    ```bash
    python scripts/stop.py --llama-port <your_llama_server_port>
    ```

3.  **Log File**:
    *   Check `logs/stop.log` for details on the stopping process.

## Configuration Notes

*   The primary method for configuring the application (ports, paths, model settings) is through the `.env` file in the project root.
*   Model configurations, such as paths to model files or specific LLM parameters, are typically defined in the `.env` file. The backend service reads these variables when loading and interacting with models. Ensure these are correctly set before starting the services.

## Troubleshooting

*   **Port Conflicts**:
    *   If services fail to start due to "address already in use," check which process is using the port:
        *   Linux/macOS: `sudo lsof -i :<port_number>`
        *   Windows: `netstat -ano | findstr :<port_number>` (then find PID in Task Manager)
    *   Change the conflicting port (`LOCAL_APP_PORT`, `LOCAL_FRONTEND_PORT`) in your `.env` file and restart.
*   **Build Failures (Llama.cpp)**:
    *   Ensure a C++ compiler (g++, Clang, or MSVC) and CMake are correctly installed and available in your system's PATH.
    *   Check `logs/setup.log` or console output from `setup.py` for specific CMake or compilation errors.
*   **Python/Node.js Version Issues**:
    *   Verify that your installed versions meet the prerequisites. Using tools like `pyenv` (for Python) or `nvm` (for Node.js) can help manage multiple versions.
*   **Frontend Issues (`npm install` or `npm run dev` problems)**:
    *   Ensure Node.js and npm are correctly installed and accessible.
    *   Check for network issues if `npm install` fails to download packages.
    *   If `npm run dev` fails, check `logs/frontend.log`.
    *   As a last resort for frontend dependency issues, you can try deleting the `lpm_frontend/node_modules` directory and the `lpm_frontend/package-lock.json` file, then re-run `python scripts/setup.py` to let it attempt a fresh installation of frontend dependencies.
